Sadikoi Android app

How to develop, sign and publish the app on the Play Store, and how to set up Google sign-in, invitation links and push notifications.

Overview

The mobile app is the Angular website packaged as an Android app with Capacitor. The site is built into dist/Sadikoi/browser, then copied into the Android project (android/), which opens in Android Studio.

Why the origin is https://localhost

In the app, the page is loaded from the phone, not from the website, so window.location.origin is https://localhost. That's why shared links use environment.siteUrl, and why the API must allow this origin.

Setup & development

Requirements

  • Node and npm, with the project dependencies installed (npm install).
  • Android Studio. It ships with Java and keytool. This guide assumes it is installed in /opt/android-studio: adjust the paths if yours is elsewhere.
  • adb (Android SDK) and a phone in developer mode, connected over USB.
Java is not on the PATH

keytool and ./gradlew fail with command not found or JAVA_HOME is not set. Use Android Studio's Java: prefix the command with JAVA_HOME=/opt/android-studio/jbr, or add these lines to ~/.zshrc:

~/.zshrc
export JAVA_HOME=/opt/android-studio/jbr
export PATH="$JAVA_HOME/bin:$PATH"

Development loop

Build the site and copy it into the Android project
npx ng build && npx cap sync android
Open Android Studio (then ▶ Run to launch on the phone)
npx cap open android
Regenerate the icon and splash screen from assets/
npm run assets

Run it again after every change to the Angular code, a Capacitor plugin or capacitor.config.ts. An app launched from Android Studio is signed with the debug key (see next section).

Initial project setup (history, already done) 
npm i @capacitor/core
npm i -D @capacitor/cli

iOS (npm i @capacitor/ios, npx cap add ios) requires a Mac and is not set up yet.

Signing keys

Android only installs signed apps. The signature proves that every version comes from the same author: an update signed with a different key is rejected. With the Play Store there are two keys, plus the debug key for development.

What a fingerprint (SHA-1 / SHA-256) is

Each key has a fingerprint: an identifier computed from the key. Google Sign-In and App Links check that the app is signed by a key whose fingerprint has been declared. A key has two fingerprints: a SHA-1 (short) and a SHA-256 (long). Each service asks for one or the other (see SHA fingerprints).

Create the upload key (once)

  1. Generate the key file, outside the project folder: 
    /opt/android-studio/jbr/bin/keytool -genkeypair -v -keystore "$HOME/sadikoi-upload.jks" -keyalg RSA -keysize 2048 -validity 10000 -alias upload

    The command asks for a password, then your name and a few details (press Enter to leave them empty). Confirm with yes. The key password is the same as the file password.

  2. Create android/keystore.properties. This file is ignored by git (android/.gitignore), and so are *.jks files:
    android/keystore.properties
    storeFile=/home/<user>/sadikoi-upload.jks
storePassword=<password>
keyAlias=upload
keyPassword=<password>

    storeFile must be an absolute path (~ doesn't work) or a path relative to android/app/. android/app/build.gradle reads this file to sign the release build. If it doesn't exist, the release is simply left unsigned.

  3. Back up the .jks file and its password somewhere else (password manager, USB drive...).
Never commit the key or its password

The repository is public. If you lose the upload key, Google support can reset it (Play Console → App integrity), but it is a slow process.

Alternative: the Android Studio wizard

Build → Generate Signed App Bundle or APK… → Android App Bundle → Create new… (path of the .jks, password, alias upload, validity 25 years). The output is then in android/app/release/. The command line method above is still recommended: it can be repeated with npm run android:release.

Build the signed AAB

The Play Store requires an Android App Bundle (.aab), not an APK. One script does everything: production build of the site, Android sync, then build and signing.

JAVA_HOME=/opt/android-studio/jbr npm run android:release

Output: android/app/build/outputs/bundle/release/app-release.aab

Check the signature

cd android && JAVA_HOME=/opt/android-studio/jbr ./gradlew :app:signingReport

In the Variant: release section, you should see Config: release with the SHA-1 and SHA-256 of your upload key. Config: none means keystore.properties is missing or wrong.

First upload

  1. Test and release → Internal testing → Create new release → upload app-release.aab.
  2. Accept Play App Signing, which is offered automatically: Google then creates the app signing key.
  3. Get that key's fingerprints: Test and release → App integrity → App signing. It shows the SHA-1, the SHA-256 and a Digital Asset Links JSON snippet. The "Upload key certificate" section must show the same fingerprints as your upload key.
  4. Declare these fingerprints (next section), then install the app from the test link.

Required forms (no code)

  • Store listing: 512×512 icon, 1024×500 feature graphic, phone screenshots, descriptions.
  • Privacy policy: https://sadikoi.missclick.net/privacy
  • Account deletion: https://sadikoi.missclick.net/delete-account
  • Data safety, content rating, target audience, ads declaration, app category.

SHA fingerprints: what goes where

Simple rule: SHA-256 → assetlinks.json (App Links) and SHA-1 → Google Cloud (Google Sign-In). Firebase doesn't need them for push notifications.

KeyWhere to find its fingerprintsNeeded for
App signing (Google) Play Console → App integrity → App signing Required the app installed from the Play Store
Upload (yours) ./gradlew :app:signingReport, Variant: release. Also shown in Play Console under "Upload key certificate". Optional a release APK/AAB installed manually
Debug ./gradlew :app:signingReport, Variant: debug Dev the app launched over USB from Android Studio
Read the fingerprints of a .jks file directly
/opt/android-studio/jbr/bin/keytool -list -v -keystore "$HOME/sadikoi-upload.jks" -alias upload

The debug key belongs to each machine (~/.android/debug.keystore): it is different on another computer, so its fingerprints have to be declared again there.

Google Sign-In

Google blocks its sign-in page inside a WebView (error disallowed_useragent). In the app, sign-in therefore goes through the native plugin @capgo/capacitor-social-login (src/app/components/google-login/google-login.component.ts). On the website, it is still the regular Google button.

OAuth clients

OAuth clientWhere it is usedRole
WebApp: src/environments/secrets.ts (googleClientId, git-ignored). Backend: GOOGLE_CLIENT_BROWSER_IDThe token returned by Google is issued for this ID, on the website and in the app. The backend verifies it.
Android (one per SHA-1)Nowhere in the codeLets Google recognize the app (package name + SHA-1). Must be in the same Google Cloud project as the Web client.
No Android ID goes into the secrets

GOOGLE_CLIENT_MOBILE_ID in Sadikoi-API/src/.google.secrets stays as it is. It is a fallback in case Google issues a token for the Android ID, but in practice it is not used.

Declare a key

  1. Google Cloud Console → APIs & Services → Credentials, in the Web client's project.
  2. Create credentials → OAuth client ID → type Android.
  3. Package name com.missclick.sadikoi, and the key's SHA-1.
  4. Repeat for each key: an Android client only accepts one SHA-1. At a minimum, create the one for the app signing key.

No new AAB and no backend change are needed. It can take a few minutes to apply.

App Links (links that open the app)

Links to https://sadikoi.missclick.net/group/invitations/… and /reset-password/… (invitations, emails) open the app instead of the browser when it is installed.

  • Android: the autoVerify intent filter in AndroidManifest.xml declares these paths.
  • Website: public/.well-known/assetlinks.json lists the allowed SHA-256 fingerprints. Android downloads it when the app is installed to verify the link.
  • Angular: src/app/services/deep-link/deep-link.service.ts listens to appUrlOpen and opens the right page.

Update assetlinks.json

Add the SHA-256 to the sha256_cert_fingerprints list without removing the others, then redeploy the site. Play Console provides a ready-made JSON snippet, but it only contains the app signing key: don't replace the whole file with it.

Check the live file (200, application/json, no redirect)
curl -i https://sadikoi.missclick.net/.well-known/assetlinks.json

Test on the phone

The state must be "verified"
adb shell pm get-app-links com.missclick.sadikoi
Simulate opening a link
adb shell am start -a android.intent.action.VIEW -d "https://sadikoi.missclick.net/group/invitations/test"
Android only verifies on install

If the app was installed before the new file went live, uninstall and reinstall it, or run the verification again:

adb shell pm verify-app-links --re-verify com.missclick.sadikoi

Push notifications (Firebase)

Firebase is only used to send push notifications. It is a separate project from the Google Cloud project used for Google sign-in. SHA fingerprints are not needed.

Publish an update

  1. Increase versionCode (always +1, Play rejects a number already used) and versionName in android/app/build.gradle.
  2. JAVA_HOME=/opt/android-studio/jbr npm run android:release
  3. Play Console → the target track → Create new release → upload the new .aab.
android/app/build.gradle
versionCode 2
versionName "1.1"

Fingerprints don't change between versions: nothing to redo in Google Cloud or assetlinks.json.

Troubleshooting

keytool: command not found / JAVA_HOME is not set

Java is not on the PATH. Use /opt/android-studio/jbr/bin/keytool and JAVA_HOME=/opt/android-studio/jbr ./gradlew …, or edit ~/.zshrc (see Setup).

Google sign-in: DEVELOPER_ERROR / code 10

The SHA-1 of the key that signed the installed app is not declared in any Android OAuth client of the project. Installed from Play → app signing SHA-1. Release installed manually → upload SHA-1. Launched from Android Studio → debug SHA-1.

Google sign-in: disallowed_useragent

The web sign-in was opened in the WebView. In the app, the button must use the native plugin: check that Capacitor.isNativePlatform() is true and that the plugin is synced (npx cap sync android).

Links open the browser instead of the app
  • curl -i on assetlinks.json: it must return 200, application/json, with no redirect.
  • The SHA-256 of the key that signed the installed app must be in the list.
  • Reinstall the app or run pm verify-app-links --re-verify, then check with pm get-app-links.
The app crashes on startup after adding push

google-services.json is missing from android/app/ while pushNotificationsEnabled is true. Add the file, or set the option to false.

No notification received
  • Notification permission granted on the phone (Android 13+).
  • .firebase-service-account.json present on the server, no FCM error in the API logs.
  • The phone sent its token to the API (push.service.ts logs).
Logged out / CORS errors in the app

Check that the API allows the https://localhost origin with credentials, and that cookies are SameSite=None; Secure. Quick test:

curl -si -X OPTIONS https://sadikoi.missclick.net/api/ -H "Origin: https://localhost" -H "Access-Control-Request-Method: POST" | grep -i access-control
Play rejects the AAB: "version code already used" or "signed with the wrong key"

Increase versionCode. For the key: the AAB must be signed with the upload key registered in Play Console (compare with signingReport).
