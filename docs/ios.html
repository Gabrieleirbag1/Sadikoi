Sadikoi iOS app

How to publish the app on the App Store from Linux, with no Mac and no iPhone: the iOS build runs on a macOS machine provided by GitHub Actions, and everything else is done in a browser.

Overview

The iOS app is the same Angular build as the website and the Android app, packaged with Capacitor. Building and signing an iOS app requires Xcode, which only runs on macOS. That one step is done by a GitHub Actions macOS runner. The rest happens on Linux (code, Xcode project files) or in a browser (Apple Developer, App Store Connect).

What is different from Android

You never hold the signing key in a keystore that you build with locally: the certificate and profile are stored as GitHub secrets and used by the runner. Push notifications go through Apple (APNs), and Apple reviews every version before it is published, usually within 24 to 48 hours.

Private repository = paid minutes

The repository is public, so macOS runners are free. If it ever becomes private, every macOS minute counts as 10 minutes of the free quota (2,000 minutes per month on the free plan, so about 200 macOS minutes). A full build takes about 10 to 15 minutes.

Apple Developer account

  1. Enroll at developer.apple.com/programs/enroll with your Apple ID.
    • Individual: fastest (hours to 2 days). Your legal name is shown as the seller on the App Store.
    • Organization: the company name is shown, but you need a D-U-N-S number (free, takes 1 to 2 weeks) and a legal entity.
  2. Note your Team ID: developer.apple.com → Account → Membership details.
  3. Accept the agreements: App Store Connect → Business. The free apps agreement is accepted with the program. The Paid Apps agreement and the tax/banking forms are only needed for paid apps or in-app purchases.
  4. EU Digital Services Act: App Store Connect → Business → Compliance → declare whether you are a trader. Without this declaration, the app cannot be distributed in the European Union. A trader's address, phone number and email are shown publicly on the App Store page. A free app made outside of any business can usually be declared as non-trader: check the definition that applies to you.

Add the iOS platform (once)

Capacitor 8 creates iOS projects with Swift Package Manager, so no pod install is needed and the command works on Linux.

Create ios/
npm i @capacitor/ios
npx ng build
npx cap add ios
npx cap sync ios

Commit the ios/ folder. Its own .gitignore already leaves out the generated files (App/App/public, capacitor.config.json): the workflow recreates them with npx cap sync ios.

If npx cap add ios fails on Linux

Run it once on a macOS runner and download the result: a workflow with a single job (npm ci, npx ng build, npx cap add ios), then actions/upload-artifact with path: ios. Unzip it into the project and commit it.

Icon and splash screen

Add --ios to the assets script in package.json (next to --android), then run it again. It writes ios/App/App/Assets.xcassets.

package.json → scripts.assets (beginning)
npx --yes @capacitor/assets@3.0.5 generate --android --ios --iconBackgroundColor '#0b74d5' ...
The App Store icon must not be transparent

A 1024×1024 icon with an alpha channel is rejected on upload (ITMS-90717). Check it, and flatten it on the brand color if needed:

identify -format '%[channels]\n' ios/App/App/Assets.xcassets/AppIcon.appiconset/*.png
convert icon.png -background '#0b74d5' -alpha remove -alpha off icon.png

Configure the Xcode project from Linux

Without Xcode, the native settings are edited in text files. Plist files are plain XML. The project file (project.pbxproj) is edited with a Ruby script, so that no setting is written by hand into it.

4. Project settings (Ruby script)

The files above must be referenced in the project, and the App target must be set to manual signing. Signing settings go into the project rather than onto the xcodebuild command line: on the command line they would also apply to the Swift packages, which fail with "does not support provisioning profiles".

scripts/ios-configure.rb
#!/usr/bin/env ruby
# Native iOS settings that Xcode would normally set. Run from the project root:
#   APPLE_TEAM_ID=XXXXXXXXXX ruby scripts/ios-configure.rb
# Safe to run again: files already referenced are left as they are.
require 'xcodeproj'

TEAM_ID = ENV.fetch('APPLE_TEAM_ID')
PROFILE = ENV.fetch('IOS_PROFILE_NAME', 'Sadikoi App Store')

project = Xcodeproj::Project.open('ios/App/App.xcodeproj')
target = project.targets.find { |t| t.name == 'App' }
group = project.main_group['App']

def reference(group, name)
  group.files.find { |f| f.path == name } || group.new_reference(name)
end

# Copied into the app (resources). Add 'GoogleService-Info.plist' here if you use Firebase on iOS.
resources = ['PrivacyInfo.xcprivacy'].map { |name| reference(group, name) }
resources.each do |ref|
  target.add_resources([ref]) unless target.resources_build_phase.files_references.include?(ref)
end
# Read when signing, not copied.
reference(group, 'App.entitlements')

target.build_configurations.each do |config|
  s = config.build_settings
  s['DEVELOPMENT_TEAM'] = TEAM_ID
  s['CODE_SIGN_ENTITLEMENTS'] = 'App/App.entitlements'
  s['TARGETED_DEVICE_FAMILY'] = '1,2' # iPhone + iPad: iPad screenshots are required
  next unless config.name == 'Release'
  s['CODE_SIGN_STYLE'] = 'Manual'
  s['CODE_SIGN_IDENTITY'] = 'Apple Distribution'
  s['CODE_SIGN_IDENTITY[sdk=iphoneos*]'] = 'Apple Distribution'
  s['PROVISIONING_PROFILE_SPECIFIER'] = PROFILE
end

project.save
puts 'ios/App/App.xcodeproj updated'
Run it, then commit ios/ and the script
APPLE_TEAM_ID=XXXXXXXXXX ruby scripts/ios-configure.rb
git diff --stat ios/

IOS_PROFILE_NAME must be the exact name given to the provisioning profile on developer.apple.com (next section).

Certificates, profiles and keys

Apple uses four different credentials. Click one to see what it does:

Step by step

  1. Register the App ID: developer.apple.com → Certificates, IDs & Profiles → Identifiers → + → App IDs → App. Description Sadikoi, explicit Bundle ID com.missclick.sadikoi. Tick the capabilities Push Notifications and Associated Domains.
  2. Create the certificate request on Linux, outside the project folder: 
    mkdir -p ~/sadikoi-ios && cd ~/sadikoi-ios
openssl genrsa -out distribution.key 2048
openssl req -new -key distribution.key -out distribution.csr \
  -subj "/emailAddress=you@example.com/CN=Your Name/C=FR"
  3. Create the certificate: Certificates → + → Apple Distribution → upload distribution.csr → download distribution.cer.
  4. Make the .p12 (certificate + private key in one file, protected by a password you choose): 
    openssl x509 -inform DER -in distribution.cer -out distribution.pem
openssl pkcs12 -export -legacy -inkey distribution.key -in distribution.pem \
  -name "Apple Distribution" -out distribution.p12

    -legacy uses the encryption that macOS's security tool always accepts (OpenSSL 3 defaults to a newer one).

  5. Create the provisioning profile: Profiles → + → Distribution → App Store Connect → App ID com.missclick.sadikoi → the certificate from step 3 → name it Sadikoi App Store → download the .mobileprovision.
  6. Create the APNs key: Keys → + → name Sadikoi APNs → tick Apple Push Notifications service (APNs) → download the .p8 (only once!) and note its Key ID.
  7. Create the App Store Connect API key: App Store Connect → Users and Access → Integrations → App Store Connect API → Team Keys → + → name GitHub Actions, access App Manager → download the .p8 (only once!) and note the Key ID and the Issuer ID shown above the list.
  8. Back up ~/sadikoi-ios (key, .p12 and its password, both .p8 files) somewhere safe, outside the repository.
Never commit these files

The repository is public. distribution.key, .p12 and .p8 files only go into GitHub secrets (encrypted) and your backup. If one leaks, revoke it on developer.apple.com / App Store Connect and create a new one.

Push notifications on iOS

On Android, the API sends notifications through Firebase (FCM). On iOS, @capacitor/push-notifications gives an APNs token, not an FCM token: sent to FCM as it is, it is rejected. Two ways to fix it:

OptionAppAPI
A. API sends straight to APNs Recommended Unchanged except two small fixes. No Firebase SDK on iOS. A small APNs sender, chosen when the token's platform is ios (already stored).
B. Firebase on iOS too Replace the push plugin with @capacitor-firebase/messaging on both platforms (returns an FCM token), and adapt SadikoiMessagingService on Android. Unchanged (plus an apns block in the messages). The APNs key is uploaded to Firebase.

Option A doesn't touch the Android app, which already works. The rest of this section describes it.

App: forward the token from AppDelegate

The Capacitor push plugin needs these two methods in ios/App/App/AppDelegate.swift, inside the AppDelegate class:

ios/App/App/AppDelegate.swift
func application(_ application: UIApplication, didRegisterForRemoteNotificationsWithDeviceToken deviceToken: Data) {
    NotificationCenter.default.post(name: .capacitorDidRegisterForRemoteNotifications, object: deviceToken)
}

func application(_ application: UIApplication, didFailToRegisterForRemoteNotificationsWithError error: Error) {
    NotificationCenter.default.post(name: .capacitorDidFailToRegisterForRemoteNotifications, object: error)
}

App: don't create Android channels on iOS

PushNotifications.createChannel is not implemented on iOS and throws. In push.service.ts, start() calls createChannels() before register(): on iOS, the error stops it and the token is never sent. Only create them on Android:

src/app/services/push/push.service.ts → start()
if (Capacitor.getPlatform() === 'android') {
  await this.createChannels();
}

App: tags on iOS

Android notifications carry a tag (chat-12...). On iOS, the API sets the same value as apns-collapse-id, which becomes the notification's identifier: a new notification with the same id replaces the previous one. In removeFromTray(), match on the id when there is no tag:

src/app/services/push/push.service.ts → removeFromTray()
const delivered = notifications.filter(n => tags.includes(n.tag ?? n.id));

App: "dismiss" messages while the app is closed

On Android, SadikoiMessagingService removes notifications when the group is seen on another device, even when the app is closed. On iOS, the JavaScript doesn't run in the background: the same job is done in AppDelegate.swift (add import UserNotifications at the top):

ios/App/App/AppDelegate.swift
// Background push from the API ("dismiss"): the group was seen on another device,
// its notifications leave this phone's tray. Their identifier is the API's tag (apns-collapse-id).
func application(_ application: UIApplication,
                 didReceiveRemoteNotification userInfo: [AnyHashable: Any],
                 fetchCompletionHandler completionHandler: @escaping (UIBackgroundFetchResult) -> Void) {
    guard userInfo["action"] as? String == "dismiss", let tags = userInfo["tags"] as? String else {
        completionHandler(.noData)
        return
    }
    let ids = tags.split(separator: ",").map(String.init)
    UNUserNotificationCenter.current().removeDeliveredNotifications(withIdentifiers: ids)
    completionHandler(.newData)
}
Best effort on iOS

iOS limits background pushes (a few per hour) and doesn't deliver them at all if the user force-quit the app from the app switcher. When the app is opened, clearGroupNotifications() still cleans up the group on screen.

API: send to APNs

In Sadikoi-API/src/notifications.py, ApnsClient sends to Apple over HTTP/2 (httpx[http2]), authenticated with a JWT signed by the APNs .p8 key (PyJWT), renewed every 45 minutes. The notifications are still built once, in the FCM format (build_message, build_dismiss_message): to_apns() converts them when they are sent.

FCM messageAPNs request
notification (title, body)aps.alert, sound: default, apns-push-type: alert, priority 10
data.tagapns-collapse-id (the notification's identifier on the phone) and aps.thread-id
data (route, channel, tag)Top level of the payload, read by the app as notification.data
Data only (dismiss)aps.content-available: 1, apns-push-type: background, priority 5, expires after a day

_send_all looks up each token's platform (sent by the app at registration): ios goes through apns, the rest through fcm. Invalid tokens (410, BadDeviceToken, Unregistered) are deleted, as with Firebase. Without the APNs files, iPhones get nothing and Android works as before.

Put the files next to the Firebase service account, in Sadikoi-API/src/ (git-ignored, mounted read-only by server_sadikoi.sh, left out of the image):

Sadikoi-API/src/.apns-key.p8
(the AuthKey_XXXXXXXXXX.p8 file of the "Sadikoi APNs" key, renamed)
Sadikoi-API/src/.apns.secrets
APNS_KEY_ID=XXXXXXXXXX
APNS_TEAM_ID=TEAMID

Then rebuild the image (new dependencies in requirements.txt) and restart the container. The API uses the production APNs server (api.push.apple.com), which serves TestFlight and App Store builds.

Option B: Firebase on iOS too
  • Firebase console → Project settings → add an iOS app (com.missclick.sadikoi) → download GoogleService-Info.plist into ios/App/App/ and add it to the resources list of scripts/ios-configure.rb.
  • Project settings → Cloud Messaging → Apple app configuration → upload the APNs key (.p8) with its Key ID and your Team ID.
  • Replace @capacitor/push-notifications with @capacitor-firebase/messaging: getToken() instead of register() + registration, events notificationReceived / notificationActionPerformed. On Android, SadikoiMessagingService must then extend the new plugin's service (check its class name in node_modules/@capacitor-firebase/messaging/android). Follow the plugin's README for the iOS AppDelegate changes.
  • API: add an apns block to the FCM messages, with the same headers as above (apns-collapse-id, and apns-push-type: background + content-available: 1 for dismiss).

Google Sign-In on iOS

The app already uses the native plugin @capgo/capacitor-social-login (src/app/components/google-login/google-login.component.ts). On iOS, it needs an iOS OAuth client of its own.

  1. Google Cloud Console → APIs & Services → Credentials, in the same project as the Web client → Create credentials → OAuth client ID → type iOS → Bundle ID com.missclick.sadikoi, Team ID. No SHA fingerprint on iOS.
  2. Note the client ID (XXXX-yyyy.apps.googleusercontent.com) and its reversed form (com.googleusercontent.apps.XXXX-yyyy, also shown on the client's page as iOS URL scheme). The reversed form goes into CFBundleURLSchemes in Info.plist (Configure Xcode).
  3. Add the iOS client ID to src/environments/secrets.ts and pass it to the plugin:
    src/environments/secrets.ts
    export const secrets = {
    googleClientId: '...web client...',
    googleIosClientId: '...ios client...',
};
    google-login.component.ts → getNativeSocialLogin()
    await SocialLogin.initialize({
  google: {
    webClientId: secrets.googleClientId,
    iOSClientId: secrets.googleIosClientId,
    // Asks Google for a token meant for the backend (the Web client).
    iOSServerClientId: secrets.googleClientId,
  },
});
  4. API: depending on the Google SDK version, the token's aud can be the iOS client ID. Add it to the accepted audiences in google_login_handler (Sadikoi-API/src/auth.py), e.g. a new GOOGLE_CLIENT_IOS_ID in .google.secrets, next to GOOGLE_CLIENT_BROWSER_ID and GOOGLE_CLIENT_MOBILE_ID.
Check the plugin's iOS setup page

Some versions of the plugin also need a line in AppDelegate.swift to handle the URL Google opens at the end of the sign-in. Read the iOS section of the Google provider in the plugin's documentation for the version in package.json.

Sign in with Apple is not required

App Review guideline 4.8 only requires it (or an equivalent) when a third-party login is the only way in. Sadikoi also has its own email + password accounts.

Universal Links (links that open the app)

iOS equivalent of the Android App Links: https://sadikoi.missclick.net/group/… and /reset-password/… open the app. deep-link.service.ts already handles appUrlOpen on both platforms: nothing to change in Angular.

  1. The entitlement applinks:sadikoi.missclick.net (App.entitlements) and the Associated Domains capability on the App ID.
  2. The file public/.well-known/apple-app-site-association (no extension), next to assetlinks.json:
    public/.well-known/apple-app-site-association
    {
  "applinks": {
    "details": [
      {
        "appIDs": ["TEAMID.com.missclick.sadikoi"],
        "components": [
          { "/": "/group/*" },
          { "/": "/reset-password/*" }
        ]
      }
    ]
  }
}
  3. Serve it as JSON. Apache doesn't know the type of a file without extension: add this to .htaccess:
    .htaccess
    <Files "apple-app-site-association">
  ForceType application/json
</Files>
  4. Redeploy the site (build_project.sh) and check. Apple doesn't read the file from your server but from its CDN, which can take up to a day to refresh:
    200, application/json, no redirect
    curl -i https://sadikoi.missclick.net/.well-known/apple-app-site-association
curl -s https://app-site-association.cdn-apple.com/a/v1/sadikoi.missclick.net
How to test

Tap a link in Notes, Messages or Mail. A link typed in Safari's address bar never opens the app, and if the user once chose "Open in Safari" from the banner, iOS remembers it: long-press the link → "Open in Sadikoi" to switch back.

Public repository: never run this workflow on pull requests

The workflow below only starts by hand (workflow_dispatch) or on a tag you push. Secrets are not given to pull requests from forks, but a pull_request_target trigger would expose them: don't add one.

2. The workflow

.github/workflows/ios.yml
name: iOS release

on:
  workflow_dispatch:
  push:
    tags: ['ios-v*']

jobs:
  testflight:
    runs-on: macos-26
    timeout-minutes: 45
    steps:
      - uses: actions/checkout@v4

      - uses: maxim-lobanov/setup-xcode@v1
        with:
          xcode-version: latest-stable

      - uses: actions/setup-node@v4
        with:
          node-version: 22
          cache: npm

      - name: Restore the git-ignored secrets file
        env:
          SECRETS_TS: ${{ secrets.SECRETS_TS }}
        run: printf '%s\n' "$SECRETS_TS" > src/environments/secrets.ts

      - name: Build the site and copy it into ios/
        run: |
          npm ci
          npx ng build --configuration=production
          npx cap sync ios

      - name: Install the certificate and the provisioning profile
        env:
          P12_BASE64: ${{ secrets.IOS_P12_BASE64 }}
          P12_PASSWORD: ${{ secrets.IOS_P12_PASSWORD }}
          PROFILE_BASE64: ${{ secrets.IOS_PROFILE_BASE64 }}
        run: |
          KEYCHAIN="$RUNNER_TEMP/build.keychain-db"
          KEYCHAIN_PASSWORD="$(openssl rand -base64 24)"
          echo "$P12_BASE64" | base64 --decode > "$RUNNER_TEMP/distribution.p12"
          security create-keychain -p "$KEYCHAIN_PASSWORD" "$KEYCHAIN"
          security set-keychain-settings -lut 21600 "$KEYCHAIN"
          security unlock-keychain -p "$KEYCHAIN_PASSWORD" "$KEYCHAIN"
          security import "$RUNNER_TEMP/distribution.p12" -k "$KEYCHAIN" -P "$P12_PASSWORD" -A -t cert -f pkcs12
          security set-key-partition-list -S apple-tool:,apple: -k "$KEYCHAIN_PASSWORD" "$KEYCHAIN"
          security list-keychains -d user -s "$KEYCHAIN" $(security list-keychains -d user | tr -d '"')

          PROFILE="$RUNNER_TEMP/profile.mobileprovision"
          echo "$PROFILE_BASE64" | base64 --decode > "$PROFILE"
          UUID=$(security cms -D -i "$PROFILE" | plutil -extract UUID raw -)
          # Xcode 16+ reads the first folder, older versions the second.
          for dir in "$HOME/Library/Developer/Xcode/UserData/Provisioning Profiles" \
                     "$HOME/Library/MobileDevice/Provisioning Profiles"; do
            mkdir -p "$dir"
            cp "$PROFILE" "$dir/$UUID.mobileprovision"
          done

      - name: Archive
        run: |
          # Same version as the Android app; the build number only has to go up.
          VERSION=$(sed -n 's/.*versionName "\(.*\)".*/\1/p' android/app/build.gradle)
          xcodebuild archive \
            -project ios/App/App.xcodeproj -scheme App -configuration Release \
            -destination 'generic/platform=iOS' \
            -archivePath "$RUNNER_TEMP/App.xcarchive" \
            MARKETING_VERSION="$VERSION" CURRENT_PROJECT_VERSION=${{ github.run_number }}

      - name: Export the .ipa
        run: |
          xcodebuild -exportArchive \
            -archivePath "$RUNNER_TEMP/App.xcarchive" \
            -exportOptionsPlist ios/ExportOptions.plist \
            -exportPath "$RUNNER_TEMP/export"

      - name: Upload to App Store Connect (TestFlight)
        env:
          ASC_KEY_ID: ${{ secrets.ASC_KEY_ID }}
          ASC_ISSUER_ID: ${{ secrets.ASC_ISSUER_ID }}
          ASC_KEY_P8_BASE64: ${{ secrets.ASC_KEY_P8_BASE64 }}
        run: |
          mkdir -p ~/.appstoreconnect/private_keys
          echo "$ASC_KEY_P8_BASE64" | base64 --decode > ~/.appstoreconnect/private_keys/AuthKey_$ASC_KEY_ID.p8
          xcrun altool --upload-app --type ios \
            --file "$RUNNER_TEMP/export/App.ipa" \
            --apiKey "$ASC_KEY_ID" --apiIssuer "$ASC_ISSUER_ID"

      - name: Keep the .ipa
        uses: actions/upload-artifact@v4
        with:
          name: sadikoi-ios-${{ github.run_number }}
          path: ${{ runner.temp }}/export/App.ipa
          retention-days: 14

      - name: Remove the keychain
        if: always()
        run: security delete-keychain "$RUNNER_TEMP/build.keychain-db" || true

3. Run it

  • GitHub → Actions → iOS release → Run workflow, or gh workflow run ios.yml, or push a tag: git tag ios-v1.0.11 && git push origin ios-v1.0.11.
  • Follow it with gh run watch. When it is green, the build shows up in App Store Connect → TestFlight after 5 to 30 minutes of processing. Apple also sends an email if something is wrong in the build (missing purpose string, icon...).

Screenshots

Only the 6.9" iPhone size is required (Apple scales it down for the other iPhones): 1320 × 2868 portrait (1290 × 2796 is also accepted), 1 to 10 images. The Play Store screenshots (1080 × 1920, 9:16) don't fit this ratio.

  • Render the app the same way as the Play screenshots, with a browser at 440 × 956 CSS pixels and a device scale factor of 3, which gives 1320 × 2868.
  • Or take them on the borrowed iPhone (a Pro Max gives the right size directly) or from the simulator in CI (xcrun simctl io booted screenshot).
  • They must show the real app: a caption frame is fine, a fake screen is not.

The app also runs natively on iPad (TARGETED_DEVICE_FAMILY = "1,2"), so the 13" iPad size is required too: 2064 × 2752 portrait (2048 × 2732 is also accepted), 1 to 10 images. Render them with a browser at 1032 × 1376 CSS pixels and a device scale factor of 2, or from an iPad simulator in CI. App Review also tests the app on an iPad, so check that the layout works at that width.

Once a year

  • The Developer Program renews every year: if it lapses, the app is removed from the App Store.
  • The distribution certificate and the profile expire after a year. The published app keeps working; only new builds fail. Create a new certificate (same CSR steps) and profile, then update IOS_P12_BASE64, IOS_P12_PASSWORD and IOS_PROFILE_BASE64.
  • The APNs key and the App Store Connect API key don't expire.

Troubleshooting

No signing certificate "iOS Distribution" found / No profiles for 'com.missclick.sadikoi' were found
  • The "Install the certificate" step must show 1 identity imported. Check the .p12 password and that it was made with -legacy.
  • PROVISIONING_PROFILE_SPECIFIER (Ruby script) and ExportOptions.plist must use the profile's exact name.
  • The profile must be of type App Store Connect and include the certificate in the .p12.
… does not support provisioning profiles, but provisioning profile … has been manually specified

A signing setting was passed on the xcodebuild command line, which applies it to the Swift packages too. Keep the signing settings in the project, on the App target only (Ruby script).

Provisioning profile … doesn't include the aps-environment / associated-domains entitlement

The capability was enabled on the App ID after the profile was created. Edit the profile on developer.apple.com (or create it again), download it and update IOS_PROFILE_BASE64.

Upload refused: The bundle version must be higher than the previously uploaded version

The build number (CURRENT_PROJECT_VERSION) was already used for this version, e.g. after renaming the workflow, which resets github.run_number. Add an offset: CURRENT_PROJECT_VERSION=$(( ${{ github.run_number }} + 100 )).

Email from Apple: ITMS-90717, ITMS-90683, ITMS-91053
  • ITMS-90717 Invalid App Store Icon: the 1024 icon has an alpha channel (flatten it).
  • ITMS-90683 Missing purpose string: a NS…UsageDescription is missing from Info.plist (camera, photo library...).
  • ITMS-91053 Missing API declaration: add the reason it names to PrivacyInfo.xcprivacy.
Push: the registration event never fires on iOS
  • The two AppDelegate methods are missing.
  • createChannels() throws on iOS before register() (check the Push notifications setup failed log).
  • The app was built without the aps-environment entitlement.
Push: APNs answers BadDeviceToken or DeviceTokenNotForTopic

BadDeviceToken: the token comes from a debug build (sandbox) and was sent to the production server, or the reverse. TestFlight and App Store builds use production. DeviceTokenNotForTopic: apns-topic must be the bundle ID, and the APNs key must belong to the same team.

Google Sign-In crashes: Your app is missing support for the following URL schemes

The reversed iOS client ID is not in CFBundleURLSchemes in Info.plist, or it doesn't match iOSClientId.

Google Sign-In: the API answers Token has wrong audience

The token was issued for the iOS client ID. Add it to the audiences accepted by google_login_handler.

Links open Safari instead of the app
  • Apple's CDN (app-site-association.cdn-apple.com/a/v1/sadikoi.missclick.net) must return the file. It can take up to a day after a change.
  • appIDs must be TEAMID.com.missclick.sadikoi with your real Team ID.
  • Test from Notes or Messages, not from Safari's address bar. Long-press → "Open in Sadikoi" if Safari was chosen once.
Logged out at every launch / CORS errors

The API must allow the capacitor://localhost origin with credentials (already done for iOS, see the Android guide). CapacitorHttp and CapacitorCookies must stay enabled in capacitor.config.ts.

curl -si -X OPTIONS https://sadikoi.missclick.net/api/ -H "Origin: capacitor://localhost" -H "Access-Control-Request-Method: POST" | grep -i access-control
The workflow can't find Xcode or the macos-26 runner

Check the runner images available in GitHub's actions/runner-images repository and use the latest macOS label. Apple only accepts uploads built with a recent Xcode (the current major version), so latest-stable is the safest choice.
